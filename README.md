# وكيل صوتي باستخدام LiveKit

مشروع Python لوكيل صوتي يتحدث بالعربية، يتصل بخادم LiveKit مستضاف ذاتياً، ويستخدم Gemini لتوجيه الحوار وفهم الطلب وطرح سؤال توضيحي عند الحاجة. يرسل الأسئلة وطلبات الخدمات إلى DarAI وينطق ردها مباشرة. يستخدم OpenAI أو Gemini لتحويل الصوت بحسب الإعداد، وتتطلب الخدمات مفاتيح API وقد تترتب عليها رسوم.

يرسل الوكيل أسئلة المستخدم إلى قناة DarAI عبر WebSocket باستخدام `DARAI_BASE_URL` و`DARAI_API_KEY` في `.env.local`. المصادقة تحدد القناة من المفتاح؛ معرف القناة محفوظ للمرجع. أنشئ محادثة صوتية جديدة بعد أي تغيير في إعدادات البيئة أو الكود. عند تعذر الرد تنتهي محاولة DarAI لهذه الجلسة، ويمكن بدء جلسة جديدة للمحاولة مجدداً. هذا الربط تجريبي ولا يتضمن تخزين أحداث دائم أو استئناف تسليم مضمون للإنتاج.

لاستخدام Gemini لتحويل الصوت والنطق بدلاً من OpenAI، أضف `VOICE_PROVIDER=gemini` و`GOOGLE_API_KEY=...` إلى `.env.local` وأعد تشغيل الوكيل. يظل DarAI مصدر الإجابات. للعودة إلى OpenAI استخدم `VOICE_PROVIDER=openai`. تكامل Gemini تجريبي ويجب اختبار توفر النماذج وجودة النسخ والنطق قبل الاعتماد عليه.

## نسخة Gemini Live التجريبية

الهوية المعتمدة هي المستند الجديد `prompts/cac_bank_voice.md`، ويحمّلها `persona.py` مع حدود الأدوات المتاحة. تطبق في Gemini Live وفي توجيه النسخة السابقة، مع نبرة عربية واضحة بلمسة يمنية خفيفة. أمثلة المستند ليست حقائق مصرفية معتمدة. لا توجد صلاحية تنفيذ معاملات أو تحويل مكالمات أو الاطلاع على الحسابات.

لا يغيّر هذا الملف إعدادات الوكيل داخل DarAI؛ إجاباته تُنطق مباشرة، لذلك يجب ضبط طولها وأسلوبها وسياسة حماية البيانات في DarAI أيضاً. تعليمات الهوية لا تمثل ضماناً لمنع تسريب البيانات في التسجيلات أو النصوص؛ هذه النسخة ليست جاهزة لاستقبال أسرار أو بيانات مصرفية حقيقية. اختلاف الجرس بين Gemini Live وTTS قد يستمر رغم توحيد تعليمات الأداء.

تستخدم النسخة `dialogue_flow.py` لإدارة طلب نشط واحد، ومنع تكرار السؤال المطابق أثناء الانتظار، وإلغاء الأصوات المعلقة عند وصول الرد. يتوقف الصوت عند كلام العميل دون إلغاء البحث تلقائياً. أداة تصحيح السؤال تستبدل الطلب، وأداة الإلغاء توقف الانتظار محلياً؛ قد تستمر معالجة الطلب السابق في DarAI. يصدر تحديث انتظار واحد بعد 12 ثانية. اختبارات هذا المنسق: `python -m unittest test_dialogue_flow -v`.

هذه الضوابط تتحقق عندما يختار Gemini الأداة الصحيحة؛ لا تضمن تصنيف كل مقاطعة أو منع كل كلام معلوماتي يولّده النموذج. عبارات الانتظار ما زالت تُولَّد عبر TTS وقد يتأخر صوتها. يلزم اختبار صوتي لقياس ذلك وللتأكد من عدم تداخل صوت Gemini مع الرد الخارجي.

شغّل `.\.venv\Scripts\python agent_live.py console` لتجربة المحادثة المباشرة. ينطق الوكيل عبارة انتظار أثناء استعلام DarAI ويستخدم TTS مستقل لنطق ردها. هذا المسار تجريبي: توجيه الأسئلة يعتمد على النموذج، ولا يضمن قرار التوجيه أو الإلغاء عند المقاطعة في كل الحالات. اختبره قبل استخدامه مع العملاء. يظل `agent.py` متاحاً كالمسار السابق.

## تجربة محلية على Windows

يلزم Python 3.10 أو أحدث وDocker Desktop قيد التشغيل. افتح PowerShell في هذا المجلد:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env.local
```

ضع مفاتيح الخدمات الفعلية في `.env.local` محلياً، ولا تشارك الملف. يتطلب `agent_live.py` إعداد `GOOGLE_API_KEY` و`DARAI_BASE_URL` و`DARAI_API_KEY`؛ كما يتطلب الوكيل السابق `OPENAI_API_KEY` عند اختيار مزود OpenAI. يستخدم LiveKit المنفذ 17980 لتجنب التعارض مع مشروع آخر:

```powershell
docker compose up -d
```

في نافذة PowerShell أولى، شغّل وكيل الصوت:

```powershell
.\.venv\Scripts\python agent_live.py dev
```

وفي نافذة ثانية، شغّل واجهة الويب وخادم إصدار الرموز المؤقتة:

```powershell
.\.venv\Scripts\python voice_server.py
```

افتح `http://localhost:8000` من المتصفح على نفس الجهاز، واسمح باستخدام الميكروفون عند الطلب. زر الميكروفون يبدأ وينهي الاتصال، ويصدر الخادم رمز LiveKit قصير العمر ومحدوداً بغرفة واحدة وصلاحيات صوتية. يستخدم LiveKit منفذ UDP المحلي `17982` للصوت؛ عنوان ICE في Compose مضبوط على loopback للاختبار المحلي فقط، لذا لا تفتح منافذه للإنترنت بهذه الإعدادات.

تستخدم الواجهة مكتبة LiveKit JavaScript من jsDelivr، لذا يلزم اتصال بالإنترنت لتحميل المكتبة. عند النشر، استخدم HTTPS وWSS، واضبط `WEB_ORIGIN` على أصل الموقع الدقيق. لا تستخدم مفاتيح التطوير أو هذه الخدمة المحلية كإعداد إنتاج.

لاختبارات خدمة إصدار الرموز:

```powershell
.\.venv\Scripts\python -m unittest test_voice_server test_dialogue_flow -v
```

للاختبار المباشر بالميكروفون على نفس الجهاز يمكن بدلاً من تشغيل العامل داخل LiveKit تشغيل الوكيل التفاعلي:

```powershell
.\.venv\Scripts\python agent.py console
```

وضع console قد يتطلب تثبيت أدوات الصوت المحلية. لإيقاف خادم التطوير استخدم `docker compose down`.

## معاينة واجهة الويب

واجهة عربية صوتية فقط: عند تشغيل `voice_server.py` بالتعليمات أعلاه تصبح واجهة المتصفح وخدمة إصدار الرموز متاحتين معاً على `http://localhost:8000`.

## النشر على خادمك

ملف Compose المرفق للتطوير المحلي فقط ويستخدم مفاتيح عامة معروفة؛ لا تفتحه للإنترنت. لإعداد خادم إنتاج استخدم [دليل LiveKit للآلات الافتراضية](https://docs.livekit.io/transport/self-hosting/vm/) لتوليد إعدادات Docker وTLS وTURN، ثم ضع عنوان `wss://` ومفتاح وسر LiveKit الحقيقيين في `.env.local` للوكيل. يتطلب ذلك نطاقاً وسجلات DNS ومنافذ شبكة مناسبة. شغّل الوكيل على خادمك باستخدام `python agent.py start` بعد تثبيت الاعتماديات؛ يمكن تشغيله منفصلاً عن خادم LiveKit. لا تنشر ملف الأسرار، ولا تستخدم مفاتيح التطوير في الإنتاج.

للاتصال من المتصفح أو الهاتف يلزم إبقاء خدمة الويب وإصدار الرموز خلف HTTPS، وعدم كشف أسرار LiveKit أو مفاتيح DarAI في العميل. يستخدم الخادم المحلي المرفق إعدادات تطوير، وليس بديلاً عن ضوابط المصادقة وتحديد المعدل ومراقبة إساءة الاستخدام اللازمة لخدمة عامة.
