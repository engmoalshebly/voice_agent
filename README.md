# وكيل DarAI الصوتي

وكيل صوتي عربي يعمل فوق LiveKit. يستخدم Gemini لإدارة الحوار، وتأتي الحقائق من قناة المطورين في DarAI فقط. يتضمن واجهة ويب بـReact وخدمة تصدر رموز اتصال قصيرة العمر.

> نسخة تجريبية. ليست جاهزة لاستقبال أسرار أو بيانات مصرفية حقيقية، ولا تنفذ معاملات أو تحويلات أو اطلاعاً على الحسابات.

## البنية

```
src/voice_agent/
  config.py            إعدادات موحدة تُتحقق عند الإقلاع (ConfigError)
  domain/              منطق خالص بلا اعتماد على LiveKit أو مزودين
    dialogue.py        DialogueFlow: طلب واحد نشط، استبدال، إلغاء، انتظار الصمت، فشل صادق
    routing.py         التحقق من قرار الموجّه (وضع pipeline)
    phrases.py         كل الجمل الثابتة المنطوقة
    ports.py           واجهات KnowledgeBase وSay
  application/
    persona.py         الهوية المعتمدة (prompts/cac_bank_voice.md) + حدود الصلاحيات
    router.py          TurnRouter بسجل محدود
  infrastructure/
    darai.py           عميل DarAI باتصال WebSocket دائم وإعادة اتصال تلقائية
    providers.py       المكان الوحيد لأسماء النماذج ومزودي الصوت
    logs.py            سجلات JSON
  entrypoints/
    worker.py          عامل LiveKit واحد: VOICE_MODE=cascade | live | pipeline
    token_api.py       الواجهة + /api/token (فحص الأصل، حد طلبات، رؤوس أمان) + /healthz /readyz
web/                   React 19 + Vite + TypeScript + Tailwind 4 + @livekit/components-react
tests/                 pytest للمجال والتوجيه والإعدادات وخدمة الرموز
```

**مسار المكالمة:** يطلب المتصفح رمزاً من `/api/token`، ثم ينضم إلى غرفة LiveKit. ينضم العامل إلى نفس الغرفة. عندما يحتاج النموذج معلومة يستدعي `ask_darai`، فيتولى `DialogueFlow` الاستعلام وجمل الانتظار ونطق الرد. ينشر العامل مرحلة البحث في الخاصية `darai.lookup`، وتعرضها الواجهة للمستخدم.

**الواجهة:** تعرض كرة صوتية تتغير مع حالة الوكيل (يستمع، يفكر، يبحث، يتحدث)، ونص المحادثة مباشرة، ومؤقت المكالمة. فيها كتم للميكروفون (اختصار M) واختيار للميكروفون، ورسائل أخطاء مصنفة حسب نوعها (إذن الميكروفون، حد الطلبات، الشبكة). تُعرض من اليمين لليسار، بوضع فاتح وداكن، وعلى عرض الهاتف، وتراعي تقليل الحركة. يبدأ تسجيل الميكروفون قبل اكتمال الاتصال حتى لا تضيع أول كلمات المستخدم.

## التشغيل المحلي

يحتاج Python 3.11 أو أحدث، وNode 22، وDocker. شغّل هذه الأوامر على جهاز تطوير لا على خادم الإنتاج.

```bash
cp .env.example .env.local           # ضع المفاتيح الحقيقية محلياً فقط
python -m venv .venv && . .venv/bin/activate
pip install -e ".[test]"
docker compose up -d livekit          # LiveKit v1.9.4 بوضع التطوير
(cd web && npm ci && npm run build)

voice-agent dev                       # النافذة 1: العامل
voice-web                             # النافذة 2: http://127.0.0.1:8000
```

لتطوير الواجهة مع إعادة التحميل الفوري، شغّل `cd web && npm run dev` وافتح `http://127.0.0.1:5173`. يمرر Vite الطلبات إلى `/api` على المنفذ 8000، لذا اضبط `WEB_ORIGIN=http://127.0.0.1:5173`.

يمكن أيضاً تشغيل كل شيء داخل Docker بالأمر `docker compose --profile full up --build`.

## النشر

- الصورة واحدة بدورين: `voice-web` (الافتراضي) أو `voice-agent start`.
- ملف Compose المرفق للتطوير فقط. في الإنتاج: LiveKit مع TLS وTURN، وعنوان `wss://`، ومفاتيح حقيقية، و`WEB_ORIGIN` مطابق تماماً للأصل، و`LIVEKIT_AGENT_NAME` للتوجيه الصريح.
- اضبط `TRUST_PROXY=true` فقط خلف وكيل يعيد كتابة `X-Forwarded-For`. حد الطلبات محفوظ في ذاكرة العملية، ويحتاج Redis إذا شُغّلت أكثر من نسخة من خدمة الويب.
- لا يغيّر هذا المشروع إعدادات الوكيل داخل DarAI. ردود DarAI تُنطق كما هي، فاضبط طولها وأسلوبها وسياسة البيانات هناك.

## حدود معروفة

- قرارات الاستعلام والإلغاء والتصحيح يتخذها النموذج، ولا تُضمن في كل مقاطعة.
- إلغاء الانتظار محلي فقط؛ قد يستمر DarAI في معالجة الطلب، لذلك تُفتح محادثة DarAI جديدة بعد كل إلغاء.
- قد يختلف جرس صوت Gemini Live عن صوت TTS المستخدم لنطق ردود DarAI.

## إدارة الحوار CTM

الوضع الافتراضي `cascade`: تحويل الصوت إلى نص، حوار Gemini وأدوات DarAI، ثم صوت TTS موحد. تبقى حالة صوت المستخدم والوكيل لدى LiveKit، وتدير `DialogueFlow` حالة البحث وإصدار الرد. يمكن أن يستمر البحث أثناء استماع الوكيل؛ بدء كلام المستخدم لا يلغي البحث أو يفرض مقاطعة صوتية خارج LiveKit.

- نهاية الدور: `v1-mini` محلي صريح مع endpointing ديناميكي بين 0.3 و2.5 ثانية. يعمل النموذج على CPU، ويجب اختبار قدرته عند المكالمات المتزامنة. يمكن اختيار `VOICE_TURN_DETECTOR=vad` للرجوع إلى كشف النشاط الصوتي.
- المقاطعات: `VOICE_INTERRUPTION_MODE=vad` افتراضيًا مع استعادة المقاطعة الخاطئة. تفعيل `adaptive` يحتاج مفاتيح LiveKit Cloud المنفصلة `LIVEKIT_INFERENCE_API_KEY` و`LIVEKIT_INFERENCE_API_SECRET`. لا تستبدل مفاتيح خادم LiveKit الذاتي بمفاتيح الاستدلال.
- النطق: تنتظر الإجابة صمتًا مستقرًا، ويُعاد الانتظار إن تكلم العميل أثناء مهلة الاستقرار. حالة `answering` تستمر حتى اكتمال تشغيل الصوت أو مقاطعته. يوقف استبدال السؤال الصوت القديم ويستبعد نتيجته.
- الانتظار: إشعار واحد بعد `VOICE_NOTICE_DELAY` إذا لم يكتمل البحث. تذكير صمت واحد عند حدث الغياب، دون تكرار أثناء البحث. لا تُنهى المكالمة تلقائيًا بسبب الصمت.
- وضع `pipeline` يدعم قراري `cancel` و`status` بجمل ثابتة، إضافة إلى البحث والاستيضاح والتحية. اختيار القرار يظل معتمدًا على الموجّه.
- الاسترداد: معرف الطلب ثابت عبر إعادة الاتصال، ويُرسل آخر cursor مع المصادقة الجديدة. يعتمد منع المعالجة المكررة على عقد idempotency في Gateway. مهلة الطلب تشمل الاتصال والمحاولات، ويُغلق اتصال المصادقة الفاشل.
- تنسيق الكلام يزيل عناوين Markdown وعلامات التنسيق المحددة دون تلخيص أو حذف خيارات أو تغيير أرقام. لا توجد طبقة LLM ثانية لإعادة كتابة الرد.
- التوليد المسبق للنموذج والصوت معطل صراحةً؛ لا تنفذ أدوات استباقية قبل اعتماد دور المستخدم.
- سجلات JSON تتضمن `response_version` و`lookup_state` و`lookup_ms` و`request_id` ومعرف ارتباط Gateway عند قبول الطلب. قياسات توليد الصوت لا تعادل وحدها زمن أول صوت مسموع في المتصفح.

إعدادات إدارة الأدوار الجديدة تخص `cascade` و`pipeline`؛ يستخدم `live` إدارة الأدوار الأصلية للنموذج. نسخة LiveKit Agents مثبتة على `1.8.11` لتوافق واجهات الإعداد والمقاطعات ومفاتيح الاستدلال.

### حدود التنفيذ واختبار القبول

هذه الخدمة تستعلم من DarAI فقط. لا تضيف هذه التغييرات معاملات مصرفية أو سجل عمليات مالي دائم أو تحويلًا لموظف. تحتاج هذه الميزات عقودًا وصلاحيات وتكاملات خلفية مستقلة. كذلك لم يُستبدل مزود STT أو TTS، ولم تُفعّل خدمة استدلال سحابية تلقائيًا.

قبل النشر، اختبر مكالمات فعلية تشمل: ترددًا داخل الجملة باللهجة اليمنية، «أيوه» أثناء الرد، تصحيح السؤال أثناء البحث، إلغاء الانتظار، انقطاع DarAI بعد قبول الطلب، صمتًا أثناء البحث، وإغلاق المتصفح أثناء الاتصال. قارن زمن نهاية الكلام إلى أول صوت، والمقاطعات الخاطئة، واستهلاك CPU والتكلفة مع النسخة السابقة. الاختبارات المحلية لا تثبت جودة الصوت أو نجاح اتصال المزودين في الإنتاج.

لا تستخدم `deploy/run-voice.sh` لاعتماد هذا التغيير دون مسار نشر مُراجع: السكربت الحالي يستبدل الحاويات مباشرة. التغييرات البرمجية لا تنشر نفسها ولا تغير إعدادات التثبيت الحي.
